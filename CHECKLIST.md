# CHECKLIST — implementation status per TAXONOMY.md row

One line per table row of `TAXONOMY.md`, same order, same granularity. This file
answers exactly one question — "which taxonomy rows does the engine handle today,
and how do we know?" — so that two agents (or a human and an agent) can never
again disagree about what "close out R1" means by silently counting at different
granularities. **Count rows, not primitives.** "Sphere is supported" is not a
status; "3.2 done, 3.1 todo" is.

Division of labor: `TAXONOMY.md` stays the normative reference (never mark
status there); `ROADMAP.md` owns *when* things land (phases, dates); this file
owns *what is true on disk right now*, row by row.

Rules (mirrors ROADMAP's):

- A row is **done** only when it is true on disk and runnable, with evidence
  cited — a `.cam` fixture + golden file or a named test. No evidence, no done.
- If you land or change surface coverage, update the row in the same commit.
- If a status here contradicts the code, the code wins — fix the row.

Statuses:

- **done** — implemented and tested; evidence cited.
- **partial** — some real support; the gap is stated in Notes.
- **todo** — in 3-axis scope, nothing on disk yet.
- **unscoped** — 3-axis machinable but no ROADMAP phase item names it.
- **unrep** — undercut/re-entrant: unrepresentable by construction, deliberately
  (DECISIONS.md 2026-07 "Re-entrancy detection: unrepresentable by construction").
  Correct behavior is that the input syntax cannot express it; nothing to build.
- **phase4** — R3 row; waits for the Phase 4 mesh/kernel/sidecar work.
- **context** — form-cutter or multi-axis territory; per TAXONOMY's scope note
  it exists to explain errors, never as a to-do.
